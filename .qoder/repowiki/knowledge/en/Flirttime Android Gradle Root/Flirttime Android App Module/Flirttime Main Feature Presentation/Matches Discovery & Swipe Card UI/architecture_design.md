Single-fragment UI module under `feature.main.presentation.matches` with two sub-packages:
- Root package: `MatchesFragment` is the orchestrator — it wires the custom `SwipeCardStackView`, pill tabs (People / Quick Moments / Interests), the interests section, and bottom action buttons. It consumes `MockMatchProfileProvider` to feed cards and delegates navigation through `AppNavigator`. The fragment implements `SwipeCardStackView.OnCardSwipeListener` so swipe outcomes (RIGHT/LEFT/UP/DOWN) are handled here.
- `SwipeCardStackView`: a self-contained `FrameLayout` that owns the gesture pipeline (`onInterceptTouchEvent` → `onTouchEvent` → `startDragging` → `handleDrag` → `finishDrag` → `animateSwipeOut`). It pools exactly three `ItemMatchCardBinding` instances (top/middle/bottom) and recycles them via index rotation in `onSwipeAnimationFinished`, avoiding per-card inflation.
- `filter/`: `FiltersBottomSheetDialogFragment` extends Material `BottomSheetDialogFragment`, exposes an `onApplyFilters` callback returning `(GenderFilter, minAge, maxAge, distanceKm)`; the parent fragment sets this lambda to receive applied filters.
- `interest/`: adapters (`InterestAdapter`, `InterestPeopleAdapter`) plus item models (`InterestItem`, `InterestPersonItem`) and mock providers (`MockInterestsProvider`, `MockInterestPeopleProvider`) powering the horizontal interest chips and "People who love X" carousel.
Dependency direction is one-way: fragment → view + adapters + filter sheet; the custom view knows nothing about the fragment beyond its listener interface.
