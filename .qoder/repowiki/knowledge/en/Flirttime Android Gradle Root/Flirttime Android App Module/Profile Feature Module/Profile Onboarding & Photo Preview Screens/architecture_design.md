Two independent MVVM screen pairs under `feature/profile/presentation`, each pairing an `AppCompatActivity` with a `ViewModel` that delegates to `UserRepository` from the domain layer.

- `intro/`: `ProfileActivity` renders the full-name / display-name / DOB / gender / about form, hosts `GenderSelectionDialog` and `DobDialogNew` via callback interfaces (`OnGenderSelectedListener`, `OnDateSelectedListener`), performs local validation (all fields filled + confirmed available username) and navigates to `Destination.ProfileVerification` on success. `ProfileViewModel` exposes two `StateFlow<Resource<T>>` streams (`usernameCheckState`, `updateProfileState`) and debounces availability checks by cancelling the previous coroutine after a 500 ms delay; it also normalizes DOB strings into `YYYY-MM-DD` before calling `userRepository.updateProfile`.
- `preview/`: `PicturePreviewActivity` reads an image URI from `AppNavigator.EXTRA_IMAGE_URI`, displays it in a gesture-capture view, offers a clickable Privacy Policy link (via `ClickableSpan`), and either retakes or uploads the photo through `PicturePreviewViewModel.uploadProfilePhoto`. On upload success it navigates to `Destination.GestureVerification`.

Navigation is centralized through `AppNavigator` with typed `Destination` values; both Activities use `EdgeToEdgeHelper.setupEdgeToEdge` and observe flows inside `repeatOnLifecycle(Lifecycle.State.STARTED)` launched from `lifecycleScope`. DI is via Koin (`org.koin.androidx.viewmodel.ext.android.viewModel`).
