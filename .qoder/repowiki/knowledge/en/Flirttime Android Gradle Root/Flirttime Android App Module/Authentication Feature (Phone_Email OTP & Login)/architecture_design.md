Follows a three-layer clean architecture inside the `com.flirttime.feature.auth` package:
- `domain/repository/AuthRepository.kt` declares the feature's use-case surface as Kotlin `Flow<Resource<T>>` methods for phone/email OTP request/verify/resend, country listing, and legacy Google/phone login.
- `data/network/AuthApiService.kt` is a Retrofit interface mapping those endpoints under `api/v1/auth/{phone,email}/...` to typed data models in `data/model/AuthModels.kt` (`OtpRequest`, `VerifyOtpRequest`, `ResendOtpRequest`, `VerifyOtpResponseData`, `AuthUserDto`, `CountryItem`, etc.).
- `data/repository/AuthRepositoryImpl.kt` implements the domain interface, wraps calls in `safeApiCall`/`safeRawApiCall`, emits `Resource.Loading` before each call, runs on `Dispatchers.IO`, and on success persists tokens/user profile via `SessionManager`.
- `presentation/` contains Activities (`LoginActivity`, `LoginInputActivity`, `OtpActivity`, `SelectCountryActivity`) plus their ViewModels (`LoginInputViewModel`, `OtpViewModel`). ViewModels expose `StateFlow<Resource<T>>` state back to the UI and delegate all I/O to `AuthRepository`. Navigation between screens goes through `AppNavigator` / `Destination` from `core.navigation`.
Dependency direction is strictly one-way: presentation → domain.repository → data.*; the feature depends on `core.network`, `core.database.SessionManager`, and `core.navigation` but exposes no internal types outside its package.
