The `app` module is the Android application entry point (`FlirtTimeApplication`) that bootstraps Koin at process start via `startKoin { modules(appModule) }`. All cross-cutting concerns live in `core/` (networking via Retrofit/OkHttp, session storage, connectivity observer, image cropping, navigation, UI widgets), while each business capability lives under `feature/<name>` with its own data/domain/presentation split. The central wiring file `di/AppModule.kt` is the sole composition root: it registers shared singletons (SessionManager, NetworkConnectivityObserver, OkHttpClient, Retrofit, ApiService + per-feature ApiServices) and binds each feature's repository interface to its concrete implementation plus all ViewModels via `viewModelOf`. Features consume these abstractions through constructor injection; there are no direct cross-feature dependencies — inter-feature communication goes through the shared `AppNavigator` or the network/session layer. A legacy Java calendar view (`calendarview/`) sits alongside the Kotlin code as an embedded third-party component.
